# ふりかえり・フィードバック

ふりかえり・フィードバックを、ファイル保存まで完結させる。

## 指示内容

$ARGUMENTS

## 定義（どちらを求められているか最初に見極める）

- **フィードバック＝成果物に向く**：スライド・ブログ等のプロダクトへの指摘
  （内容・構成へのツッコミ、抜けている問い）。その時点の成果物に紐づくスナップショット
- **ふりかえり＝プロセスに向く**：作業の進め方・協働の仕方への内省
  （何がうまくいったか、どこで詰まったか、次はどう進めるか）。
  スクラムのレトロスペクティブの意味で、繰り返し実施して履歴を重ねる
- 越境した指摘（ふりかえり中に成果物の問題に気づいた等）は、分割せず**主目的のファイル**に含める

## 進め方

1. 対象ファイルを特定する（指示になければ直近の作業対象を確認する）
2. フィードバックの姿勢・順序は CLAUDE.md の「知的コンバット」に従う
   （①内容・構成へのツッコミ → ②意外な視点・広い問い。クッション表現なし）
3. チャットで内容を提示する
4. **ファイルに保存して完結させる**。チャット止まりで終えない——チャット上の内容は
   次のセッションで失われるため、保存までがふりかえり・フィードバックの完了

## 保存ルール

- フィードバック → 対象ファイルと同じフォルダに `{ファイル名}_feedback.md`
- ふりかえり → 対象ファイルと同じフォルダに `{ファイル名}_retrospective{N}.md`
  （既存の N を確認して次の番号を使う）
- slides/・blogs/ での作業が典型だが、他のフォルダでも同じ規約で保存する

## 発動条件

「ふりかえりをしよう」「フィードバックしてくれるかな」等、自然文で求められた場合も
このコマンドの手順に従う。
