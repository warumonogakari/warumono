# レビュー（crit 起動）

Hiroshi さんのレビュー要求を、crit スキルによるインラインコメントレビューで完結させる。

## 発動条件

- 「レビューして」「レビュして」「レビューさせて」「レビューしよう」等、
  自然文でレビューの意思が示された場合
- `/review` として明示的に呼ばれた場合

テキストでファイルを貼って口頭ツッコミをもらう形式は使わない。crit のブラウザ
インラインコメントが Hiroshi さんのレビューワークフロー。

## 進め方

1. **対象を特定する**：指示に対象があればそれ。なければ直近の作業対象
   （直前に作成・編集したファイル群、プラン、ドキュメント）。複数ファイルなら
   フォルダごと一括で載せる
2. **crit スキルを起動する**（Skill ツールで `crit` を呼び、その手順に従う）
   - `crit <対象パス>` をバックグラウンドで実行し、URL をそのまま伝える
   - Finish Review まで待つ（先に進まない）
3. **コメント対応ループ**
   - 各コメントに対応（ファイルを Edit）し、`crit comment --reply-to` で返信
     （複数件は `--json` で一括、author は `Claude Code`、返信は日本語）
   - `--resolve` は付けない（解決はレビュアーの判断）
   - `crit --session <id>` で次ラウンドを開始し、`approved: true` になるまで繰り返す
4. **承認後**：対応内容を要約して報告する
5. **日本語表現の指摘を蓄積する**（下記）。その後、作業の次ステップへ

## 日本語表現の好みの蓄積

蓄積先：`Obsidian/Documents/Obsidian/Clippings/日本語表現の好み.md`

承認後、今回のレビューコメントを見直して以下を行う。

1. **抽出**：日本語の**表現**に関する指摘だけを拾う（語の選択、言い回し、文の長さ、
   敬体・常体、修飾の付け方など）。コードの誤り・事実誤認・構成や論旨への指摘は対象外
2. **追記**：抽出したものを「指摘ログ」テーブルに1行ずつ追記する。
   **媒体（スライド／ブログ／技術文書）を必ず埋める**——
   場面が記録されていないとルールが全媒体に一律適用され、文体が硬直する
3. **昇格の提案**：ログ内に同種の指摘が2件以上そろったら、ルール昇格を Hiroshi さんに提案する。
   ❌／⭕の実例と「場面」を書式どおりに埋めた案を示し、**承認を得てから**ルール欄へ移す。
   自動昇格はしない
4. **矛盾の申告**：既存ルールと反する指摘が来た場合は昇格させず、
   「ルールを更新するか、この場面を例外にするか」を問う

該当する指摘がなければ何もしない。無理に1件ひねり出さない。
