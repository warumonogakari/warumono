# commit（git commit + push スクリプト運用）

CLAUDE.md の git操作ルール（「Claudeがスクリプトを生成 → Hiroshiさんが内容確認 → 確認後は
Claudeが `bash <パス>` で実行してよい」）を、毎回ルールを読み解かずに一発で回すための
コマンド。手順の実体は CLAUDE.md 側にあり、このファイルはその適用手順の固定化。

## 発動条件

- 「コミットして」「commitして」等、コミットの意思が示された場合
- `/gitcommit` として明示的に呼ばれた場合

## 進め方

1. **状態確認**：`git status` / `git diff`（staged・unstaged 両方）/ 直近の `git log` を並行実行
2. **対象を絞る**：ユーザーの指示があればそれに従う。指示がなければ、直前の作業に関係する
   ファイルのみを対象にする。無関係な untracked ファイルは含めない（含めるか迷う場合は聞く）
3. **コミットメッセージを起草**：直近のコミットの文体に合わせる。「なぜ」を中心に1〜2文
4. **スクリプトを生成**：スクラッチパッドディレクトリに保存。内容は
   `git add <対象ファイル>` → `git commit -m "$(cat <<'EOF' ... EOF)"` → `git push` → `git status`
   （`-A` や `.` は使わない。ファイルを明示指定する）
5. **表示して確認を待つ**：スクリプトの中身をそのまま提示し、Hiroshi さんの確認（「ok」等）を待つ。
   確認前に実行しない
6. **実行**：確認後、`bash <スクリプトのパス>` で実行する。確認済みスクリプトは実行前に
   編集しない（変更が要る場合は再生成・再確認）
7. **push後の反映確認**：`!` を使った実機確認が必要な場合はユーザーに依頼する
   （Claude が代理で `!` は打てない）

## 注意

- rebase / reset / 強制操作など push 以外の git 操作はこのコマンドの対象外
  （CLAUDE.md の「その他」区分どおり必ず確認）
- push 先が private/公開範囲に影響する場合や、force push が必要な状況ではこのコマンドを
  使わず個別に確認する
