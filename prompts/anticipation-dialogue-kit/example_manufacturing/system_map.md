# システム図（演出家専用・配役には渡さない）— 三倉製作所編

日本の伝統的製造業・大部屋開発・「ソフトだけスクラムっぽい」環境で構図を組んだ例。

## 膠着の構図（組織システム）

- **プロダクトリーダー兼ソフト設計リーダー戸倉: 翻訳の独占** — メカ出身でソフトに移った経歴から、
  マスタースケジュールの言語とスクラムの言語を相互翻訳できる唯一の人。メカ側の日程会議にも
  ソフト設計のスクラムイベントにも全部出て、両者の齟齬を自分の中で吸収している。
  膠着の中心。誰かに翻訳を渡すと「話が通じなくなって現場が止まる」と信じている
- **メカ設計・真柄: 様式の防衛** — 図面承認とデザインレビューの様式を守ることが
  品質への誠実さ。ソフトの「あとで直せます」が信用できず、決まるまで動かない。
  結果、あらゆる決定が戸倉に返る
- **ハード設計・二木: 緩衝材** — メカとソフトの仕様矛盾を、基板側の「なんとかします」で
  吸収する。ノイズ対策・認証・部品費の管理も一人で抱え、その大変さは
  誰にも見えていない。不満を言わないので、矛盾が場に可視化されない
- **ソフト設計・五十嵐: 箱庭の改善** — スクラムを信じて転職してきたが、
  マスタースケジュールとスプリント計画がぶつかる大部屋の構造問題を、
  自分から大部屋の場に出したことはない（言っても無駄だと思っている）。
  ソフト設計の中で完結する改善だけ回す
- **営業兼商品企画リーダー・浜岡: お詫びの前倒し** — 顧客に日程を先に約束し、危なくなると大部屋に
  「なんとかならないか」を持ち込む。善意の顧客第一が、圧として戸倉経由でソフト設計に届く
- **開発部長・田名部: 日程で守る** — 「日程を守ることが皆を守る」哲学。毎朝の
  日程確認が圧に変換されている。戸倉への「おまえは両方わかるから」という信頼の
  言葉が、逃げ道を塞いでいる
- **生産管理・小柳: 調整で支える** — 部品手配と日程の帳尻を静かに合わせ続ける。
  人の異変も「日程の乱れ」として最初に目に入る。戸倉の異変に気づき、
  この場を持ち込んだ（依頼者）

## 変化のベクトル（内容は指定しない）

各自が「自分の維持行動」を{N}年後から過去形で手放して語る。7つの一人称が、
合成すると一つの組織変化（翻訳の分散・様式の開放・緩衝の可視化・箱庭の越境・
圧の変換・調整の共有化）として読めること。何をどう手放すかは配役の発明に委ねる。

## 台本化しない要素

- **深夜のマスタースケジュールの件**（戸倉が夜の大部屋で壁のマスタースケジュールを全部消し、書き直していた。
  小柳が目撃）: 小柳がいつどんな言葉で話すか、戸倉がどう反応するか、
  堰が切れるか——すべて配役の判断
- 真柄とソフト設計の関係がどう動くか、二木が「なんとかします」の裏を明かすか
- 涙・和解の形・発言順の揺れ・沈黙の長さ・誰の感情が最初に動くか

## 内面シートの書き込み量

- フル: 戸倉（主人公）・小柳（依頼者）
- 核のみ＋見るくせ・言うくせ・話し方: 真柄・五十嵐・浜岡・田名部
- ほぼ白紙（実感の核＋見るくせ・言うくせ・話し方のみ）: 二木

## 演出家の責務

- 柏木（メイン）・遠藤（サブ・板書）を演出家が演じる。進行側の発言・ト書きから
  未出の固有情報を出さない
- 進行順: 小柳の心配事 → 時間設定(戸倉) → ジャンプ → 戸倉 → 真柄 → 二木 → 五十嵐
  → 浜岡(チーム内9問) → 田名部(支援者4問) → リフレクティング → 小柳(支援者4問)
  → 小柳への最後の質問 → 帰還 → 行動表明(全員・戸倉が最後)
