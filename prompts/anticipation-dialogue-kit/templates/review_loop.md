# レビューループ — シナリオライターの運用

このキットの想定ユーザー（シナリオライター）は、1回生成して終わりではなく、
**レビューを重ねるほどポリフォニーが自分の現場に近づいていく**ループを回す。

```
初期設定（ケース作成）
  → 最初のシナリオ生成
  → シナリオライターのレビュー（インラインコメント推奨）
  → LLMが反映（下の2段階）
  → 接地ノートの更新
  → 次のrun / 次のケースへ
```

## 反映は2段階で行う

レビュー指摘を受けたLLM（演出家セッション）は、指摘を**2度**使う:

1. **局所反映**: 指摘された箇所を直す。`test_checklist.md` の修復の原則に従う
   （事実・声を保存。配役の台詞を直すときは、本人がそう言いそうな形で）
2. **傾向の昇格**: その指摘が「この1箇所の問題」か「この現場に共通する問題」かを
   判定し、後者なら一般化ルールにして**接地ノート**に書き足す。反映先
   （シート／進行手順／確認項目）も決める

シナリオライターの現場感覚（この会社ではこう話す・この道具は使わない・
この身体の作法が自然）は、システム図にもシートにも最初から全部は書けない。
レビュー指摘だけがそれを運んでくる。だから指摘は使い捨てにしない。

## 接地ノート（`grounding_notes.md` をケースごとに置く）

フォーマット: 1指摘1エントリ。

```
### {日付} {指摘の要約}
- 指摘: {レビューコメントの内容}
- 一般化: {この現場で今後も効くルールに言い換えたもの}
- 反映先: {シート○○に追記 / facilitation_guide §○ / 確認項目}
```

演出家は次のrun開始時に接地ノートを読み込む。ノートが溜まるほど、
生成されるシナリオはその現場の語彙・作法・道具立てに近づく。

## 実例（SaaS企業ケースのレビューから）

### 例1: 説明のない「電話」は現場で浮く
- 指摘: テキスト文化のスタートアップで、行動表明の「電話します」が説明なしだと
  不自然。Slackならハドルの方が自然では
- 一般化: **登場人物がその現場の標準と違う手段を選ぶときは、本人に理由を
  語らせる**（コミュニケーション媒体は組織文化の一部。無説明の逸脱は
  作者の顔が見える）
- 反映先: 確認項目＋公開情報に「この組織の
  標準的な連絡手段」を書く

### 例2: 身体の変化を場が拾っていない
- 指摘: 強張り・視線・呼吸の身体症状のト書きがあるのに、ファシリも周囲も
  反応していない
- 一般化: **ファシリは身体症状の変化を場全体経由で拾う。ト書きは周囲の
  反応（外から見える範囲）も描く**
- 反映先: facilitation_guide §4 に恒久ルール化

## 注意

- 接地ノートは**その現場のもの**。別の組織のケースを作るときは持ち越さず、
  新しいノートを始める（持ち越すと前の現場の癖が混入する）
- ルールが増えすぎて配役の発話が慎重になってきたら（声の萎縮）、
  ノートを整理して「シートに書くべきもの」と「テストで拾えばいいもの」に
  仕分けし直す。生成時の制約は最小に保つ
